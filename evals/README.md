# 평가 루프

스킬을 고쳤을 때 **좋아졌는지 나빠졌는지 판정하는 장치**다.
이게 없으면 "좋아진 것 같다"는 인상에 의존하게 되고, 프롬프트만 계속 길어진다.

## 고정 픽스처 3종

성격이 서로 반대가 되도록 골랐다. 하나에 맞춘 튜닝이 다른 하나를 깨뜨리는지 보기 위해서다.

| 픽스처 | 도메인 | 이 픽스처가 잡아내는 것 |
|---|---|---|
| `01-wedding-scheduler` | 소비자 / 일정 조율 | 온기 있는 톤, 관계 데이터, 소유자 구분 |
| `02-b2b-ops-dashboard` | B2B / 고밀도 관제 | 정보 밀도 상한, 색 단독 전달 금지, 장시간 사용 |
| `03-commerce-product-detail` | 커머스 / 이미지 지배 | 이미지와 UI의 경쟁, 전환 CTA, 긴 스크롤 |

**01에서 통했던 여백과 톤이 02에서 그대로 통하면 그 자체가 실패 신호다.**
하네스가 도메인을 읽지 않고 기본값을 재생산하고 있다는 뜻이다.

## 실행

```bash
# 1) 각 픽스처를 파이프라인에 통과시킨다 (에이전트 작업)
#    산출물을 아래 위치에 둔다:
#      evals/runs/<run-id>/<fixture>/project.rules.json
#      evals/runs/<run-id>/<fixture>/nodes.json
#      evals/runs/<run-id>/<fixture>/shots/*.png

# 2) A게이트 일괄 실행 + 집계
scripts/eval.sh 2026-09-05-a

# 3) C게이트는 사람이 채운다
cp evals/scorecard.md evals/runs/2026-09-05-a/01-wedding-scheduler/scorecard.md
```

`nodes.json` 은 `scripts/extract-nodes.js` 를 `use_figma` 로 1회 실행해 덤프한다.
(호출 전 `figma-use` 스킬 로드 필수.)
`project.rules.json` 은 손으로 채우지 않는다 — 각 픽스처의 `design/tokens.json` 에서 `node scripts/build-rules.js` 로 생성한다.

## 범용성 시험 (팀 디자이너 B 의 방식)

심사는 "청첩장 앱을 잘 만들었나"가 아니라 **"다른 주제가 와도 통하는 하네스인가"**를 본다. 픽스처 평가와 별도로, 스킬을 크게 고쳤을 때 한 번은 이렇게 돌린다.

1. 청첩장과 겹치는 게 없는 PRD(02·03 또는 새로 지은 것)로 **0단계부터 끝까지 다시 돌린다.**
2. **Figma MCP 호출 0회** — HTML 초안까지만. 하네스의 절차만 시험하고 도구 숙련도는 배제한다.
3. 검증 질문: 청첩장 도메인 지식을 한 번도 쓰지 않고 화면 목록이 도출되는가? 하네스가 PRD 가 이미 답한 질문을 스스로 생략하는가? 도메인 고유 예외 상태가 새로 생기는가?
4. 시험 중 규칙 없이 판단으로 한 것이 있으면 사후에 규칙으로 승격한다 — 돌려보고 막힌 지점을 규칙으로 굳히는 것이 하네스 개선이 실제로 작동하는 방식이다.

## 회귀 판정

직전 런의 `summary.md` 와 비교한다. 아래 중 하나라도 해당하면 **개선이 아니라 회귀**다.

- 이전에 통과하던 픽스처가 미통과로 바뀜
- blocker 총합이 늘어남
- C게이트 항목 중 이전에 통과하던 것이 실패로 바뀜
- 미검사 blocker 수가 늘어남 (검사기 커버리지 후퇴)

세 픽스처를 모두 통과시키는 것이 목표가 아니다. **같은 이유로 계속 실패하는 항목을 찾는 것**이 목표다.
같은 항목이 3개 픽스처에서 모두 실패하면 그건 화면 문제가 아니라 스킬 문제다.

## 루프를 닫는 규칙

C게이트에서 새로 발견한 실패 유형은 **반드시**
`.claude/skills/oss-design-harness/references/aesthetic-checks.md` 에 추가한다.
좋은 예를 늘리는 것보다 탈락 패턴을 늘리는 것이 이 하네스의 품질을 올리는 유일한 방법이다.

추가 형식은 `판정 기준(수치) + 빈발 사례 + 수정 방침` 3종 세트다. 셋 중 하나라도 없으면 추가하지 않는다.
