# 모바일 디자인 납품 범위와 과업 검수

## 착수: 범위와 완료 조건

templates/delivery.md로 실행 폴더의 delivery.md를 만든다. 제작자가 유지하는 작업·검수 목록이며 고객 설문이 아니다. PRD·이번 답변에서 요구사항 ID와 역할별 핵심 과업을 추출한다. 사용자에게 화면 수를 정하게 하지 말고 필요한 화면·상태를 제안한다. 동일 화면을 여러 과업에 재사용할 수 있으며 장부를 채우려고 화면을 늘리지 않는다.

핵심 흐름은 사용자 문제의 해결에 필수인 시작부터 결과까지의 과정이다. 운영자뿐 아니라 다른 주요 역할의 진입·완료도 포함한다. PRD의 각 요구사항을 과업 또는 명시적인 제외 결정과 연결한다. 제외·축소는 이유와 영향이 있는 제안이며, 기존 사용자 결정이나 실제 동의 없이 확정하지 않는다. 사용자 무응답 때문에 범위를 축소하지 않는다.

착수 요약에는 대상 플랫폼, 포함할 역할·흐름, 제외 제안, 납품물과 완료 조건을 적는다. 기본 납품물은 편집 가능한 Figma 화면·반복 컴포넌트·스타일/토큰, 핵심 흐름의 프로토타입, 필요한 동작·상태 설명, 검수 결과와 남은 한계다. 기존 요구사항 확인에 함께 포함하고 별도 승인을 반복하지 않는다. 일정 요구가 있으면 우선순위·중간 확인 시점과 연결한다. 실행 속도를 모르면 추정임을 밝히고 납기를 보장하지 않는다.

## 과업 명세: 시안 전 작성, 화면과 함께 갱신

각 핵심 과업에 역할, 진입 조건, 현재 상태, 행동, 다음 화면·결과 상태, 차단·실패·회복 조건을 연결한다. 여러 사람이 쓰는 제품이면 행동 권한과 누구에게 어떤 결과가 보이는지 포함한다. 상태 이름만 나열하지 말고 무엇이 바뀌어야 다음 상태가 되는지 정한다. 중요한 업무 정책을 레퍼런스 동작으로 대신 결정하지 않는다.

화면은 과업을 구현하는 수단이다. 홈은 전체 설계를 대신하지 않는다. 첫 시안은 대표 화면부터 제시할 수 있지만 Figma 진입 전에는 모든 핵심 과업을 HTML의 연결된 화면·상태로 확인한다. 나머지 합의 화면은 누락 목록과 제작 계획을 남기고 최종 납품까지 완성한다. 프로토타입을 위해 실제 백엔드를 개발할 필요는 없다.

## 변경·비용 관리

- 합의 요구와 다른 동작, 읽기 어려움, 구조 파손은 결함 수정이다. 국소 수정은 자율적으로 하고 영향받는 과업·상태를 다시 검사한다.
- 방향 변경은 영향을 받는 화면·재작업을 설명하고 기존 사용자 위임 범위 안에서 진행한다. 위임 밖의 중요한 선택만 확인한다.
- 새로운 기능·역할·플랫폼은 범위 추가다. 기존 납품 범위에 자동으로 숨겨 넣지 말고 일정·우선순위 영향을 정리해 요청자의 결정과 연결한다. 원래 PRD 누락을 범위 추가로 분류하지 않는다.
- 단계별 능동 작업시간·사용자 대기·재작업, 사용자 교정과 전문가 직접 개입을 execution.md에 기록한다. 미측정은 그대로 표시한다. 사용자가 디자인을 대신 분석하거나 고친 경우와 정상적인 사업 답변·선호 제공을 구분한다.
- 동일 원인 세 번 수정 후에도 해결하지 못하면 미완성·원인·다음 선택을 알린다. 해결하지 못한 범위를 납품 완료로 바꾸지 않으며 독립적으로 가능한 나머지 작업은 계속한다.

## 최종 검수·인계

1. 요구사항 전 항목을 Figma 화면·상태 노드 또는 합의된 제외와 연결한다. 화면 수가 아니라 과업·상태의 누락 여부를 확인한다. 화면 연결, 조건부 행동, 성공·실패·회복·뒤로 가기와 데이터 유지 규칙을 개발자가 이해할 수 있게 적는다.
2. 핵심 흐름은 Figma 프로토타입으로 수행한다. 도구가 연결을 지원하지 않으면 화면별 전이 명세를 남기되 프로토타입 완료로 주장하지 않는다. 대체 납품은 사용자와 범위 변경을 합의한 경우만 가능하다.
3. A/C 검증과 모바일 Q 기준을 화면·상태별 증거에 연결한다. 모든 화면을 확인하고 동일 컴포넌트의 반복 속성 검사는 대표 인스턴스와 적용 범위를 밝힐 수 있다. 공유 컴포넌트 수정 후 영향받는 상태를 재검한다.
4. 최종 Figma에 화면·컴포넌트/스타일·흐름 설명을 찾을 수 있는 진입점과 명명 규칙을 둔다. 반복 컴포넌트의 상태·속성, 레이아웃의 늘어남/줄어듦, 에셋 출처·사용 조건 또는 미확인을 정리한다. 문구·상태·폭 변경을 검증용 복제에서 수행해 편집 가능성을 확인한다.
5. 다른 작업자의 화면 추가·문구 변경과 개발 전달 이해를 확인할 수 있으면 실제 결과와 도움 여부를 기록한다. 독립 디자이너의 시각·구조 비평, 대상 사용자의 과업 관찰은 자체 검사와 분리한다. 사람이나 도구 접근이 없으면 독립 검수 미실시로 표시하며 실제 평가를 꾸미지 않는다.

납품 차단: 합의 범위의 화면·필수 상태 누락, 핵심 과업 단절/잘못된 상태 전이, 주요 정보의 가독성 결함, Figma 편집 구조 파손. 총점·고객 선호로 상쇄하지 않는다. 해당 검사가 미검증이면 내부 검수 통과도 미확정이다. 비차단 한계는 영향과 함께 보고한다.

완료 상태는 제작 완료 / 내부 검수 통과 / 독립 검수 결과 / 고객 수용을 별도로 표시한다. 고객 확인을 기다리는 동안 제작·검수 가능한 작업을 먼저 끝낸다. 전달 메시지는 파일·페이지 링크, 완료 범위, 남은 결함·미검증과 후속 작업 방법을 짧게 제공한다. 내부 통과만으로 전문 외주 동등성·재현성·금액을 입증했다고 쓰지 않는다.
