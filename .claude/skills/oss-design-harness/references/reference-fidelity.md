# 제품 과업을 보존하는 레퍼런스 적용

## 제작 전: 행동과 시각 관계를 분리한다

delivery.md에서 이번 역할의 시작 상태, 의도한 행동, 다음 화면, 결과 상태, 차단·회복 조건을 먼저 확인한다. 화면/핵심 영역별 주 레퍼런스를 정하고 그 화면이 같은 행동 의미를 갖는지 비교한다. 모양이 같아도 동작·상태 전이가 다르면 제품에 맞게 바꾼다. 선택한 서비스에 대한 선호를 그 서비스의 모든 행동·브랜드 승인으로 확대하지 않는다.

예를 들어 상태를 표시하는 체크와 실제 업무를 완료하는 명령은 다르다. 버튼은 명세한 행동·결과로 이어져야 하며, 실제 처리를 생략한 장식용 완료 표시는 해당 과업 검증에 쓸 수 없다. 제품별 정답이나 고정 레이아웃을 이 예에서 유추하지 않는다.

## 시각 기준안

과업과 양립하는 정보 순서·타이포 위계·여백·밀도·형태·색의 역할은 관찰한 레퍼런스에 충실하게 옮긴다. 임의 테마, 근거 없는 슬로건·숫자판·장식을 추가하지 않는다. 제품의 정보량·상태·행동 차이에 필요한 변경은 정당한 설계이며 원본에 닮게 하려고 되돌리지 않는다. 전체 구성의 90~95% 같은 일률적인 목표는 사용하지 않는다.

여러 출처를 쓰면 담당 영역과 공통 타이포·간격을 연결한다. 로고·브랜드명·고유 이미지·문구는 제품에 맞게 교체한다. 미관찰 값은 추정으로 기록하고 실제 렌더로 확인한다. 원본의 이용 가능 자산과 단순 관찰 대상을 구분한다.

## 제시 전 대조

1. decisions.md에 원본 특징과 HTML 대응 영역, 유지 / 제품에 필요한 변형 / 의도치 않은 이탈 / 미검증을 기록한다. 필요한 변형에는 과업 ID와 이유를 연결한다.
2. previews/index.html에서 레퍼런스 제품 영역과 실제 HTML을 같은 표시 배율로 대조한다. 홍보 배경과 기기 목업을 제품 영역으로 계산하지 않는다. 접근 실패를 텍스트 설명으로 대체하고 대조 완료라 하지 않는다.
3. 의도치 않은 정보 위계·타이포·간격 이탈을 수정하고 증거를 남긴다. 원본과 닮았어도 핵심 과업을 수행할 수 없으면 수정 필요다.
4. 핵심 과업의 진입 → 행동 → 결과와 중요한 차단·회복을 브라우저에서 수행한다. 로컬 상태를 이용한 저장·전송 시뮬레이션은 가능하되 요청 전후 상태와 실패 결과가 설계와 일치해야 한다. 백엔드 연결은 요구하지 않는다. 단순 안내 시트나 클릭되지 않는 화면은 연결 동작을 검증한 증거가 아니다.

기준안을 실제로 보여주고 사용자 반응·선택 또는 명시적 위임을 기록한다. 중요한 대안이 없으면 두 안을 의무적으로 만들지 않는다. 사용자 첫 과업 관찰은 조작 설명보다 먼저 한다. 주요 인터뷰와 HTML Q 판정 후 선택 버전을 고정하고 최종 Figma로 전환한다.
