# C단계 — 미적·게슈탈트 판정 기준

**언제 읽나**: 화면이 렌더된 뒤 C게이트를 돌릴 때. A단계(구조 검사)만 통과한 상태로 이 문서를 건너뛰면 안 된다.

**전제**: 이 문서의 항목은 **스크린샷을 실제로 보고** 판정한다. 노드 속성 조회로 대체할 수 없다.
절차: `get_screenshot`으로 대상 프레임을 렌더 → 전체 뷰 1장 + 스크롤 상단/하단 각 1장 → 아래 항목을 순서대로 판정.
스크린샷 없이 "괜찮아 보입니다"는 C단계 미수행으로 간주하고 게이트를 통과시키지 않는다.

**판정 원칙**: 두 사람이 같은 화면을 보고 같은 결론에 도달할 수 있어야 한다.
"위계가 명확하지 않다" 같은 서술은 판정이 아니다. 어느 노드가 어떤 수치로 어긋났는지 쓴다.

---

## C-1. 섹션 간 색온도·조명 일관성

**판정**: 배경 톤의 hue가 섹션 간 15° 이상 벌어지면 실패.

- 빈발 사례: 히어로만 쿨그레이(`#F4F6F8`), 아래 섹션은 웜베이지(`#FAF7F2`) → 스크롤하면 조명이 바뀐 것처럼 보인다.
- 같은 화면 안에서 순수 회색(채도 0%)과 유채색 회색을 섞으면 실패.
- **수정 방침**: surface 토큰 하나로 통일한다. 섹션 구분은 hue가 아니라 elevation 또는 여백으로 준다.

## C-2. 시각적 위계

**판정**: 스크린샷을 3초 보고 "이 화면에서 가장 중요한 것 1개"를 지목할 수 없으면 실패.

- primary 액션이 화면에 2개 이상 동등한 강도로 존재하면 실패. 강조는 화면당 1개다.
- 인접한 텍스트 두 단계의 크기 차이가 2px 이하이면 위계가 아니라 실수로 읽힌다 → 실패.
- 크기·굵기·색을 **동시에** 3개 다 써서 강조하면 과잉. 둘까지만.
- **수정 방침**: 위계는 typography scale의 단계 차이로 만든다. 임의 크기 생성 금지.

## C-3. 여백 리듬

**판정**: 섹션 간 여백 > 섹션 내부 여백 > 요소 간 여백 순서가 깨지면 실패.

- 근접성 위반: 라벨과 그 입력필드 사이 간격이, 그 입력필드와 다음 그룹 사이 간격보다 크거나 같으면 실패. 사용자가 라벨을 아래 필드에 붙여 읽는다.
- 좌우 마진이 상하 리듬과 무관하게 정해졌으면 실패.
- **수정 방침**: spacing 스케일 값만 사용. 사이 값(예: 18px, 22px)이 나타나면 그 자체가 실패 신호다.

## C-4. 정보 밀도

**판정**: 첫 화면(스크롤 없이 보이는 영역)에 사용자가 결정해야 할 항목이 5개를 넘으면 실패.

- 구분선이 3개 이상 연속으로 나타나면 밀도 초과 신호.
- 카드 안에 또 카드(중첩 컨테이너 3겹 이상)면 실패.
- 반대 방향 실패도 본다: 화면의 60% 이상이 빈 여백이고 콘텐츠가 위쪽에만 몰려 있으면 미완성으로 판정.

## C-5. 클리셰 / AI 슬롭

**아래 중 2개 이상 해당하면 실패. B단계로 회귀한다.**

- [ ] 보라→파랑(또는 청록→핑크) 그라디언트 배경
- [ ] 이유 없는 glassmorphism / backdrop-blur 오버레이
- [ ] 모든 카드가 동일 크기인 3열 그리드
- [ ] "아이콘 + 굵은 제목 + 회색 본문 2줄" 블록의 3회 이상 반복
- [ ] 이모지를 아이콘 대용으로 사용
- [ ] 근거 없는 다크모드 기본값 (PRD에 없는데 검은 배경)
- [ ] 모든 요소에 동일한 그림자가 균일하게 깔림 (elevation 위계 없음)
- [ ] 의미 없는 통계 숫자("99.9%", "10,000+")를 채움용으로 배치
- [ ] 실제 콘텐츠 대신 "Lorem ipsum" 또는 "제목을 입력하세요"가 남아 있음

## C-6. 엣지케이스 실물 완성도

**판정**: 아래 상태를 실제로 렌더해서 보지 않았으면 C단계 미수행.

- [ ] 빈 상태 — 리스트가 0건일 때. "데이터가 없습니다" 한 줄만 있으면 실패. 다음 행동이 있어야 한다.
- [ ] 최장 문자열 — 한글 기준 텍스트를 2배로 늘렸을 때 잘리거나 레이아웃이 깨지지 않는가
- [ ] 로딩 — 로딩 중 버튼 너비가 변하면 실패
- [ ] 에러 — 무엇이 잘못됐고 무엇을 하면 되는지 둘 다 있는가

## C-7. 표면 혼합 금지

참조 시스템(`guide/reference/toss.design.md`)에서 가져온 값에 특히 적용된다.

- 모바일 제품 컴포넌트 지오메트리를 마케팅 웹에 그대로 상속시켰으면 실패
  (예: 마케팅 CTA에 모바일 xlarge 56px 높이 사용).
- 서로 다른 두 표면의 값을 평균낸 흔적이 있으면 실패
  (예: 16px radius와 7px radius를 11px로 절충).
- 근거 없이 생성된 컴포넌트가 검증된 컴포넌트와 구분 없이 섞여 있으면 실패.
  확장은 `extension`으로 명시되어야 한다.

## C-8. 지어내기 금지 (Unknowns)

- 가이드에 값이 없는 항목을 그럴듯한 기본값으로 채웠으면 실패.
- 올바른 처리는 **가장 작은 미해결 단위만 생략**하고 `design-guide.md`의 Unknowns에 기록하는 것이다.
- 가정으로 진행했다면 `source: "가정: ..."`이 남아 있어야 한다. 침묵 통과와 명시적 가정은 다르다.

## 실패 시 라우팅

| 진단 | 분기 |
|---|---|
| 표면 속성 하나의 문제 (C-1, C-3, C-7의 국소 사례) | 그 속성만 고쳐 C단계 재검. B단계로 돌아가지 않는다 |
| 국소 조정으로 안 고쳐지는 구조적 문제 (C-2, C-4, C-5) | B단계 회귀. 다른 후보 선택 또는 재발산 |
| 후보를 바꿔도 같은 이유로 계속 탈락 | 0단계 에스컬레이션. 기준 자체가 잘못 추출됐다 |

**재시도 상한: 3회.** 초과 시 사람에게 에스컬레이션한다.
최종 "이 정도면 됐다" 판단은 항상 사람이 내린다.

## 카탈로그 갱신 규칙

C단계에서 새로 발견한 실패 유형은 **반드시 이 파일에 추가**한다.
좋은 예를 늘리는 것보다 탈락 패턴을 늘리는 것이 이 하네스의 품질을 올리는 유일한 방법이다.
추가 형식: `판정 기준(수치) + 빈발 사례 + 수정 방침` 3종 세트. 셋 중 하나라도 없으면 추가하지 않는다.
