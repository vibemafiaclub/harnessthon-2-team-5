# oss-design-harness (team-5 / josh)

현업 디자이너의 판단 기준을 추출해, HTML 프리뷰를 거쳐 Figma MCP(`use_figma`)로 실제 화면을 만드는 하네스.
이 파일은 2026-09-05 하네스톤에서 "청첩장모임 스케줄러" PRD로 실제 세션을 1회 통과시키며 채운 버전입니다 — 아래 각 단계는 예시가 아니라 그 세션에서 실제로 쓴 방법과, 그 과정에서 드러난 한계를 그대로 남긴 것입니다.

## 0단계 — 요구사항 정렬

- **레퍼런스/시나리오 소싱 방법**: oh-my-design.kr/builder(440개 기업 레퍼런스, 국가·색상 필터)를 사용자가 직접 브라우징한다. 하네스는 업종/톤을 라벨형 객관식(핀테크·SaaS·커머스·콘텐츠 등)으로 1차 후보를 좁히는 데까지만 관여하고, 최종 선택과 DESIGN.md export는 항상 사용자가 한다. PRD는 파일/링크/붙여넣기 중 사용자가 고른 형태로 받는다.
- **질문 형식에 대한 솔직한 한계**: 조직 원칙("라벨형 질문 금지, 자극을 보여주고 반응을 받아라")을 0단계 전체에 적용하지 못했다 — 업종/톤 필터링에는 라벨형 객관식을 실제로 썼다. 다만 **최종 판단 기준은 라벨이 아니라 항상 DESIGN.md 원문**에서 역추출했고(아래), 원문이 있는 한 라벨은 원문보다 우선순위가 낮다고 못박는다. 시각적 판단(IA 3안)은 브라우저 시각 동반자로 실제 와이어프레임을 보여주고 반응을 받았다(라벨형이 아님).
- **판단기준 역추출 방법**: DESIGN.md의 "Do/Don't" 섹션과 컴포넌트 스타일링 표를 있는 그대로 읽고, 그 뒤에 있는 **원칙**을 이 프로덕트 맥락으로 재해석한다. 실제 사례 — 카카오 DESIGN.md의 "마케팅 옐로우(#fae100)와 로그인 옐로우(#fee500)를 절대 혼용하지 말라"는 규정은, 우리 프로덕트엔 카카오 로그인이 없으므로 문자 그대로는 적용 불가. 대신 그 배후 원칙("액센트 컬러는 항상 단일 용도로만 쓰고, 다른 의미에 전용하지 않는다")만 추출해 "신랑/신부 구분에 별도 색을 새로 만들지 않고 텍스트+아웃라인만 쓴다"는 이 프로젝트만의 규칙으로 재구성했다.
- **가정 처리**: 확정 안 된 정보는 HTML에 `data-todo="..."` 속성과 "준비 중" 표기로 남긴다(예: 확정 공유 카드의 장소 필드).
- **산출물**: `brief.md` (템플릿: `templates/brief.md`, 이번 프로젝트 실채움: `docs/wedding-scheduler/brief.md`)

## B단계 — 발산·수렴

- **독립 축 식별**: 실제로 이 프로젝트에서 나눈 축은 (1) 계정/워크스페이스 구조 — 공유계정 vs 커플공간+개별로그인 vs 완전독립, (2) 정보구조(IA) — 지인풀중심 vs 모임중심 vs 캘린더중심, (3) 모임 유형 처리 — 1:1을 별도 타입으로 분리할지 통합할지. 축을 먼저 나눈 뒤 각 축을 따로 물어서, 사용자가 무엇 때문에 그 선택을 했는지 축마다 남게 했다.
- **후보 생성 방식**: 텍스트로 답이 갈리는 축(계정구조, 모임유형)은 채팅에서 3지선다 비교표로, **시각적으로 갈리는 축(IA)만** 브라우저 시각 동반자로 와이어프레임 3안을 병렬 렌더링해 제시했다. "질문이 시각적인가"를 축마다 따로 판단한 것이 핵심 — 같은 세션 안에서도 텍스트 질문과 시각 질문을 섞어 썼다.
- **비교·수렴 방식에 대한 솔직한 한계**: 조직 원칙은 "최소 2개 이상 다른 관점(페르소나)으로 교차 비평"인데, 이번 세션은 **하네스(나) 단일 관점의 추천안 제시 + 사용자 승인**으로 수렴했다 — 다각도 페르소나 교차비평은 시간 예산상 생략했다. 이건 한계로 다음 세션에 넘긴다: TODO — 최소 2인 페르소나(예: "처음 쓰는 예비신부" / "여러 커플 초대를 동시에 받는 지인") 교차비평을 B단계에 강제로 끼워 넣을 지점.
- **산출물**: `decisions.md` (템플릿: `templates/decisions.md`, 이번 프로젝트 실채움: `docs/wedding-scheduler/decisions.md`)

## A단계 — 구조적 사실 검증

체크 카테고리는 고정, 기준값은 프로젝트별 `brief.md`에서 캘리브레이션. 이번 프로젝트 기준값과 검사기는 `scripts/audit.js`로 코드화했다(실행: `node scripts/audit.js <html경로> <css경로>`).

- [x] **컬러 팔레트 일관성** — `styles.css`의 `:root` 변수 목록 외의 hex 리터럴이 `<style>`/인라인 `style=""`에 없어야 한다. 이번 프로젝트 허용 팔레트: `--canvas #ffffff, --foreground #333333, --muted #888888, --surface #eeeeee, --border #dbdbdb, --dark #111111, --ink #000000, --yellow #fae100, --yellow-tint #fffbe0`.
- [x] **타이포 스타일 재사용** — `font-family`는 `var(--font-display)`/`var(--font-body)`만 허용, 리터럴 폰트명 금지.
- [x] **Spacing 그리드 준수** — 그리드 단위는 카카오 코퍼레이트 사이트에서 관측된 **4/6/8/16/20 리듬**(px). padding/margin 수치가 이 집합의 배수인지 검사(허용 예외: `aspect-ratio`, `border-radius`처럼 spacing이 아닌 값).
- [x] **컴포넌트 재사용률** — 반복 UI(`badge-*`, `btn-*`, `chip`, `card`, `card-white`)가 화면마다 새 클래스로 재정의되지 않고 기존 클래스를 재사용하는 비율. 목표: 신규 클래스 생성 대비 기존 클래스 재사용 ≥ 80%.
- [x] **레이어(클래스) 네이밍 semantic 여부** — kebab-case + 역할 접두어(`badge-`, `btn-`, `tab-`, `field`) 준수, 의미 없는 이름(`div1`, `box2`) 금지.
- [ ] **Variant 상태 커버리지** (hover/disabled/loading/error/empty 존재 여부) — TODO: 이번 HTML 프리뷰는 정적 목업이라 hover/disabled 상태를 CSS에 별도로 정의하지 않았다. Figma 단계에서 컴포넌트 배리언트로 반드시 채워야 할 항목으로 남긴다.

## C단계 — 미적·게슈탈트 판단

스크린샷을 실제로 렌더해서 사람이 봐야 판단 가능. 이번 세션에서 실제로 걸린 두 사례를 기준값으로 남긴다.

- [x] **여백 리듬의 체감 일관성** — 실제 발견 사례: 지인풀 화면처럼 리스트 콘텐츠가 짧으면 하단 탭바(`.tabbar`)가 화면 바닥이 아니라 콘텐츠 바로 아래(화면 중간)에 뜨는 버그. 데이터/수치 검사(A단계)로는 안 잡히고 스크린샷을 봐야만 보였다. **원인 진단**: 국소적 결함(`.tabbar`가 flex 컨테이너 바닥에 고정되지 않음) → `.tabbar { margin-top: auto; }` 한 줄로 국소 수정, B단계로 되돌아가지 않고 C단계만 재검했다.
- [x] **색온도·식별성** — 실제 발견 사례: 회신 현황판의 "무응답" 표시 점(`.dot-pending`)이 테두리색(`--border`)과 명도차가 작아 눈에 잘 안 띔. 채운 원(fill)에서 테두리만 있는 링(outline)으로 바꿔 "가능(옐로우 채움)"/"불참(회색 채움)"과 형태 자체로 구분되게 했다 — 색만으로 구분하지 않는 방식으로 수정.

### C단계 실패 시 라우팅 (이번 세션 실측)

1. **국소적 결함** → 그 속성만 고쳐 C단계 재검, B단계로 안 돌아감. (실측: 탭바 버그, dot-pending 대비 — 둘 다 이 경로로 1회씩 처리, 재시도 0회로 통과)
2. **방향 자체가 틀림** → B단계로 회귀. (이번 세션에서는 발생 안 함 — IA는 처음 추천안이 그대로 승인됨)
3. **반복 실패** → 0단계로 에스컬레이션. (발생 안 함)

재시도 상한: 3회 (이번 세션 실사용: 최대 1회). 상한 초과 시 사람에게 에스컬레이션. 최종 "이 정도면 됐다" 판단은 항상 사람(Josh)이 내렸다.
