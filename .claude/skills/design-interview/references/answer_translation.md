# 비전문가 답변 → 디자인 결정 번역표

> 출처: 팀 디자이너(noyunseo 브랜치) 0-6. 실제 디자이너가 현장에서 쓰는 표준 번역이다.
> 0-F 규칙화를 맡은 `design-judge` 브리프에 이 파일 경로를 넣는다.
> **원문을 그대로 남기고 그 아래에 번역을 적는다.** 요약으로 대체하지 않는다 — 요약하면 뉘앙스와 함께 기준이 날아간다.
> 표의 수치는 **기본값**이다. brief §3 반응 정본이나 사용자 하드 제약과 충돌하면 그쪽이 이긴다. 표에 없는 표현은 같은 방식으로 **검증 가능한 수치나 규칙**으로 바꿔 적고, 그 번역을 `provisional` 로 표시한다.

| 사용자가 한 말 | 디자인 결정 (statement 초안) | verdict_method |
|---|---|---|
| "복잡해 보여요" / "정신없어요" | 한 화면에 **동일 위계 항목 5개 이하**. 넘으면 그룹핑하거나 위계를 만든다 | C |
| "뭘 해야 할지 모르겠어요" | 화면당 **주 액션 1개**를 색·크기로 단독 구별. 경쟁 요소 제거 | C |
| "답답해요" / "빽빽해요" | 섹션 간격을 요소 간격의 **2배 이상**으로. 카드 내부 여백 상향 | A |
| "휑해요" / "허전해요" | 정보를 더 넣지 말고 **시각 요소**(아이콘·막대·아바타)를 추가. 여백은 유지 | C |
| "딱딱해요" / "사무적이에요" | 모서리 반경 상향 + 강조 색 1개 도입 + 문구를 구어체로. **장식 아이콘을 뿌리지 않는다** | A+C |
| "촌스러워요" / "싸구려 같아요" | 색 종류를 줄이고(역할 없는 색 제거) 그림자를 약화. 그라디언트 제거 | A+C |
| "글씨가 안 보여요" | 본문 대비 **4.5:1** 이상, 본문 최소 **14px** | A |
| "찾기 힘들어요" | 검색·필터를 화면 상단 고정. 목록에 그룹 구분 추가 | C |
| "한눈에 안 들어와요" | 제목과 본문 크기 차이 **1.5배 이상**. 요약 지표를 최상단에 배치 | A+C |
| "실수할 것 같아요" | 되돌리기 경로 + 확인 단계 추가. 파괴적 행동은 주 액션 색을 쓰지 않는다 | C |
| "모르겠어요" | **가정으로 기록**하고 기본값으로 진행. brief §6 가정 로그 | — |

## 갤러리·대비쌍 반응의 번역

타일 반응의 이유는 대개 축을 지목하지 않는다("깔끔함", "밋밋함"). 번역할 때는 **그 타일의 객관적 속성**(`gallery_index.json`)을 붙여 방향을 확정한다.

| 반응 | 타일 속성 | 번역 |
|---|---|---|
| "깔끔함" (좋다) | 둥근 카드형, 구분선 없음 | 형태 축 = 카드형 선호, 구분선 최소 |
| "밋밋함" (싫다) | 채도 낮음, 강조 0 | 채도 축 = 중간 이상, 강조 1개 필요 |
| "둘 다 아님" | 대비쌍 | 그 축은 **취향 공백** — 기본값 + 가정 로그, confidence provisional |

## 질문 답변이 짧을 때

"있음", "아니오", "링크만 열면 끝" 같은 답은 **질문과 짝지어야** 근거가 된다. 0-G 감사 입력의 `qa` 증거에 질문 원문을 반드시 포함한다.
