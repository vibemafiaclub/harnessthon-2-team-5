# PRD 분석 — 청첩장모임 스케줄러
## 1. 화면 흐름 후보
| 화면 | 진입 경로 | 1등 정보 후보 | 기능 매핑 |
|---|---|---|---|
| 커플 연결 온보딩 | 최초 실행 | "둘이 함께 쓰는 공간"임을 알리는 상대 초대 | §5 조건 (ASSUMPTION: PRD에 화면 미명시) |
| 홈 — 전체 조망 | 로그인 직후 기본 | 이번 주말 확정 모임 + 같은 날 겹침 경고 | F5, F6 |

## 2. 시나리오 내러티브
**A. 겹치는 주말** — 토요일 아침에 일어나 앱을 켰다고 해 봅시다. 어젯밤 신랑이 자기 대학 동기 모임을 다음 주 토요일 저녁으로 확정해 뒀는데, 신부는 같은 토요일 낮 회사 선배 모임 후보를 아직 던져 둔 상태입니다. 화면 맨 위가 "다음 주 토요일 — 확정 1건, 조율 중 1건"을 나란히 보여 주고, 낮 모임을 그날 잡으면 이동이 빡빡해진다는 걸 알아채게 해 줘야 합니다. 신부는 회사 선배 모임의 후보에서 그 토요일을 빼고 다시 보냅니다.
**B. 중복 소속과 늦은 회신** — 수요일 밤, 신부가 "동네 친구" 모임을 짜는데 지수라는 이름이 이미 대학 동기 모임에도 들어가 있습니다. 앱이 "지수는 대학 동기 모임(회신 대기)에도 있어요 — 그쪽에 두시겠어요?"라고 되물어 주면 신부는 지수를 한 자리에만 남깁니다. 그런데 그 대학 동기 모임은 마감이 내일인데 한 명이 나흘째 답이 없습니다. 앱은 미회신자 한 명을 이름으로 보여 주고, 마감이 지나면 그 사람을 빼고 최다 득표일로 확정할지 물어봐야 합니다.
## 3. 토큰 자리 목록 (값 없음)
- 진행 상태 4종(대기/확정 임박/확정/완료) → semantic color 4 + status badge variant 4 (F6)
- 회신 응답 3종(가능/불가능/미회신) → semantic color 3 + 응답 칩 variant 3 (F3)
- 소속 구분 3종(신랑 측/신부 측/양가 공동) → semantic color 3 + 아바타 링 변형 (F5)
- 관계 카테고리 N종(대학·직장·가족·동네…) → 그룹 태그 color set N (F1)
- 경보 2종(같은 날 겹침, 마감 임박) → alert/warning color + 강조 배경 surface (F5, §3)
- 40~100명 리스트 밀도 → 리스트 행 spacing scale, 이름/보조정보 2단 typography scale (F1)
- 모임 규모 2종(1:1 / 3~6인) → 카드 size variant 2 (§3)
## 4. 도메인 특수 기준 후보
- 예의 리스크: 상사·어른이 보게 되는 화면(초대·회신·확정 안내)은 캐주얼 톤이면 실례가 된다 — 초대받는 쪽은 격식 톤이 기본값.
- 공동 소유의 가시성: 두 사람이 함께 쓰므로 "누가 언제 바꿨는지"가 보이지 않으면 개인 일정앱과 구분되지 않는다(§5).
- 독촉의 온도: 마감·리마인드 UI가 지인에게 압박으로 읽히면 도구 자체를 안 쓰게 된다 — 재촉이 아니라 안내로.
- 시즌성: 3개월 쓰고 버리는 앱이므로 학습 비용이 큰 온보딩·장기 습관 유도 장치는 손해다(§3).
## 5. 인터뷰에서 확인할 미확정 사항
1. 초대받은 지인이 앱을 설치해 계정을 갖는가, 링크만 열어 회신하는가 — 유저스토리 2는 계정을 시사하지만 §4는 침묵. 화면 개수가 절반쯤 갈린다.
2. 같은 모임의 다른 참석자 명단과 각자의 회신을 지인끼리 서로 볼 수 있는가 — 프라이버시이자 화면 밀도 문제.
3. F4 "확정 공유"가 앱 안 알림인가, 카카오톡 등 외부로 나가는 링크·이미지인가 — 후자면 공유 카드 디자인이 산출물에 추가된다.
## 6. PRD 반박 목록
- [누락] 지인 측 경험이 §2 유저스토리 2에는 있는데 §4 기능에는 "회신 수합"만 있고 회신하는 화면이 없다. → 대안: 설치 없이 링크로 여는 지인용 경량 회신 화면을 1급 화면으로 설계. → 질문: "친구가 날짜를 답해 줄 때, 앱을 깔아야 한다면 답을 줄까요 아니면 그냥 카톡으로 보낼까요?"
- [문제] F1의 "여러 그룹 동시 소속"은 저장만 해결하고 유저스토리 1의 진짜 고민("어느 모임에 넣지?")을 풀지 못한다. → 대안: 편성 중 중복 인물을 경고가 아니라 배치 제안으로 되묻기. → 질문: "대학 동기이면서 직장 동료인 사람은 두 자리에 다 부르시나요, 한 자리만 부르시나요?"
- [누락] §3의 "늦은 회신"이 §4에는 마감 기한만 있고 마감 이후 무엇이 되는지가 없다. → 대안: 마감 도달 시 미회신자 제외 확정을 기본 제안으로 화면에 띄우기. → 질문: "며칠째 답 없는 친구 한 명 때문에 날짜를 못 정한다면, 그 사람 빼고 정하시겠어요?"
- [과잉] F6의 상태 4단계를 그대로 4탭·4필터로 만들면 주 2~3건 규모에 비해 화면이 무겁다. → 대안: 홈은 "지금 손대야 할 모임"만 위로 올리고 상태는 배지로 축소. → 질문: "이번 주에 신경 쓸 모임이 두세 개뿐일 때도 목록을 네 칸으로 나눠 보고 싶으세요?"
## 7. 적합성 단서
- 누가: 결혼 3개월 전 예비부부 2인의 공동 사용이 주 사용자, 1회성 부 사용자는 초대받은 지인(§5, §2-2). 사용 상황은 이동 중·밤 시간의 짧은 확인. ASSUMPTION: 연령대·기기는 PRD 무언급.
- 기대되는 신뢰감·분위기: 실수하면 사람 관계가 상하는 도구이므로 축하 무드보다 "빠뜨린 게 없다"는 안정감이 우선. ASSUMPTION: 과한 웨딩 장식은 두 사람 중 한쪽의 이탈 위험.
- 경쟁 서비스 카테고리: 일정 조율(When2meet·Doodle·네이버 폼), 웨딩 준비 앱, 연락처/관계 관리 도구.
- 플랫폼: 모바일 우선(현장 확인·즉시 회신), 대량 지인 등록에서만 데스크톱 보조. ASSUMPTION: PRD 무언급.
- 브랜드 자산: PRD에 색·로고·글꼴 명시 없음 — `[CONSTRAINT]` 해당 없음(Greenfield, §머리말).
- [HYPOTHESIS] 정돈된 — 수십 명·수십 건이 흐트러지지 않고 정리돼 보이는 느낌
- [HYPOTHESIS] 담백하게 따뜻한 — 웨딩 클리셰 없이 축하의 온도만 남긴 느낌
- [HYPOTHESIS] 가벼운 격식 — 어른에게 보여도 실례가 아닌, 그러나 딱딱하지 않은 톤
## 8. 핵심 과업 3개
1. 지인 40명을 등록하고 관계별로 묶기 (F1) — 시작 화면: 빈 지인 풀. 기대 경로: 빠른 추가 → 관계 태그 부여 → 그룹별 인원수 확인.
2. 한 모임에 날짜 후보를 보내고 회신을 모아 확정하기 (F2·F3·F4) — 시작 화면: 지인 풀. 기대 경로: 인원 선택 → 모임 만들기 → 후보·마감 설정 → 회신 현황 → 확정·공유.
3. 양쪽 확정 일정을 한 화면에서 보고 겹침 확인하기 (F5·F6) — 시작 화면: 홈. 기대 경로: 주말 단위 조망 → 같은 날 2건 경고 확인 → 해당 모임 상세로 이동.
