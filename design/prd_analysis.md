## 2. 시나리오 내러티브 2개
- **A. 토요일 아침, 예비신부 지현.** 일어나 앱을 켰다고 해 봅시다. 어젯밤 자정이 대학 동기 모임의 회신 마감이었는데 여섯 명 중 두 명이 아직 아무 말이 없습니다. 지현은 먼저 "더 기다릴까, 네 명으로 확정할까"를 판단해야 하고, 네 명이 모두 가능하다고 한 이번 달 마지막 토요일에는 이미 신랑 쪽 회사 모임이 저녁으로 잡혀 있습니다. 지현이 알고 싶은 것은 순서대로 이렇습니다 — 답이 없는 사람이 누구인지, 그 둘을 빼고도 확정할 날이 남는지, 그날 우리 둘의 일정이 겹치는지. 확정 버튼을 누르기 전에 이 셋이 한 자리에 있어야 합니다.
- **B. 평일 밤, 예비신랑 준호.** 회사 선배 민수 씨는 대학 동아리 명단에도 들어 있어 두 모임 후보에 동시에 뜹니다. 준호는 민수 씨를 어느 쪽에 넣을지 고르다가, 정작 직장 상사인 팀장님은 1:1로 따로 뵈어야 한다는 걸 떠올립니다. 준호가 두려워하는 것은 "민수 씨를 어디에도 안 넣고 지나가는 것"과 "팀장님을 단체 모임에 실수로 끼워 넣는 것" 두 가지입니다. 이름 옆에 이미 잡힌 모임이 보이지 않으면 두 실수 모두 조용히 일어납니다.
## 3. 토큰 자리 목록 (값 없음)
- 상태 색 5종(결정 필요/마감 초과/회신 대기/확정/완료) + 겹침 경고색 1종, 소유자 구분 3종(신부 쪽/신랑 쪽/공동 — §5)
- 텍스트 위계 4단(1등 정보/보조/메타/약화된 완료 항목), 밀도 스케일 2종(지인 100명 목록용 compact, 카드용 comfortable)
- 배지·칩 반경/패딩, 아바타 크기 2종, 카드 그림자·구분선, 날짜·마감 카운트다운 전용 타이포 스케일
## 4. 도메인 특수 기준 후보
- 이름 단독으로 사람이 식별되지 않는다 — 이름+관계(대학/직장)가 항상 붙어 읽혀야 하고, 연락처는 필요한 순간에만 드러난다
- 하루에 모임 3건이 겹치는 주말 칸이 잘리거나 "+2"로 뭉개지면 F5 미충족이다
- 웨딩 장식이 100명 밀도를 해치면 안 된다 — 축하 톤은 확정·공유 화면에 몰아준다
- 상사·어른 대상 1:1 모임은 실수 대가가 커서 단체 모임과 시각적으로 구별돼야 한다(§3)
## 5. 인터뷰에서 확인할 미확정 사항 (3)
1. 초대받은 지인은 앱을 설치하나, 링크만 받고 답하나 — F3 회신 화면의 로그인·설치 부담이 갈린다(PRD 침묵)
2. 신랑·신부 사이 권한 차이 — 상대가 만든 모임을 내가 확정·수정해도 되는가(§5는 "함께 쓴다"만 말한다)
3. 실수의 대가(Q5) — 잘못 확정하거나 중복 초대했을 때 되돌릴 수 있는가. 상태 순위 1·2위 확정에 직접 필요하다

## 7. 적합성 단서
- **누가**: 결혼 3개월 전 예비부부 2인이 함께(§5), 한시적 집중 사용. 부차 사용자는 여러 커플 요청을 동시에 받는 1회성 방문자인 초대 지인(§2-2)
- **분위기·신뢰감**: 빠뜨리지 않고 챙겨준다는 안정감이 먼저, 결혼 준비의 설렘이 그다음. 사무 도구처럼 차갑지도 청첩장처럼 장식적이지도 않은 중간
- **경쟁 카테고리**: 일정 조율 도구(when2meet·Doodle), 하객·청첩장 관리 앱, 개인 캘린더, 연락처 관리 / **플랫폼**: `ASSUMPTION:` 모바일 앱 우선 — PRD 미명시이나 주말 이동 중 회신·확인이 잦다(§3). 브랜드 자산 명시 없음 → `[CONSTRAINT]` 없음
- `[HYPOTHESIS]` 감성 키워드 3: **차분한 설렘** / **빠짐없이 챙김** / **부드러운 정돈**
## 8. 핵심 과업 3개
1. **지인을 관계별로 등록하고 첫 모임을 편성한다** — 시작: 홈(빈 상태) → 지인 풀 목록 → 지인 상세·편집 → 모임 편성
2. **날짜 후보를 보내고 회신을 모아 확정한다** — 시작: 모임 상세(회신 보드) → 날짜 후보 제안 → 회신 보드 → 날짜 확정 → 확정 공유
3. **주말 겹침을 확인하고 급한 모임을 끼워 넣는다** — 시작: 전체 일정 조망 → 빈 날짜 선택 → 모임 편성 → 날짜 후보 제안(§3 "2주 앞으로 다가온 시점에 갑자기 잡히는 급한 모임")
