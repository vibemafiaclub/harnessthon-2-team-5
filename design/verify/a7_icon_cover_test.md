# A검사 7 (아이콘 덮임) — 검출력 시험

> 2026-09-06 · 표적 검증. **메인이 직접 만들고 직접 검사하고 직접 눈으로 확인**했다.
> 이 파일은 두 번 덮어써졌다 — 아래 "혼선 기록" 참조.

## 판정 규칙

아이콘 안에 `visible` 한 VECTOR/BOOLEAN_OPERATION 이 ≥1 이고, 그 벡터를 덮는 불투명 노드가 없어야 PASS.

"덮는다" 3조건:
1. 노드 `opacity` ≥ 0.9 **그리고** fill `opacity` ≥ 0.9
2. 노드의 절대 경계가 벡터의 절대 경계를 포함
3. 같은 부모 안에서 벡터보다 뒤 인덱스(= 위에 그려짐)

검사 대상은 **화면 프레임 안의 INSTANCE**(D-10: 마스터는 정상, 인스턴스만 덮임).

## (1) 합성 케이스 — 케이스가 제대로 만들어졌는지 먼저 확인

만들자마자 구조를 실측했다. **이 확인을 건너뛰면 시험 자체가 무의미하다**(아래 혼선 기록).

| 케이스 | 벡터 수 | visible | 크기 | path | 덮개 사각형 | 사각형 opacity |
|---|---|---|---|---|---|---|
| `TEST Screen / good` | 1 | true | 18×17 | 1 | 0 | — |
| `TEST Screen / bad` | 1 | true | 18×17 | 1 | 1 | 1.0 |

양쪽 다 벡터가 실재하고, `bad` 에만 벡터와 **같은 색** 24×24 불투명 사각형이 벡터보다 뒤 인덱스에 있다.

## (2) 검사 결과

```
good: vectors 1, covers [],                                   verdict PASS
bad : vectors 1, covers [{lid:'duo-fg', size:[24,24], op:1}],  verdict FAIL
detector: 작동함
```

## (3) 육안 확인 — 스크린샷

`good` 은 집 아이콘이 또렷하게 보이고, `bad` 는 **초록 네모**로 보인다.
`bad` 의 렌더 결과가 사용자가 실제 탭바에서 봤던 모습과 같다(`shots/a7_case_bad.png`).

기계 판정과 눈으로 본 것이 일치한다. 둘 중 하나만으로는 이 결함을 확정할 수 없었다.

## (4) 실제 화면 — Screens 24프레임

```
framesScanned: 24
iconInstancesWithVectors: 9   (탭바 인스턴스)
visibleVectors: 90
coveredCount: 0
```

**RESULT: PASS.** D-10 케이스는 이미 고쳐져 재현되지 않았으므로 합성 케이스로 검출력을 따로 확인했다.
**결함이 없는 상태에서 PASS 가 나온 것과 검사기가 작동하는 것은 다른 사실이며, 둘 다 확인해야 검사가 의미를 갖는다.**

## 혼선 기록 (D-15 의 근거)

이 시험은 한 번 잘못된 결론에 도달했다가 되돌렸다.

1. 서브가 1차 완료 보고: `good=PASS, bad=FAIL, DETECTOR 작동함` — 이때 `__TEST__` 페이지가 존재했다.
2. 메인이 `__TEST__` 페이지를 **삭제**하고 리포트를 작성했다.
3. **같은 서브가 나중에 다시 실행**되어 2차 보고를 냈다: `good=PASS(벡터 0), bad=PASS(벡터 0) → 검사기 결함`. 그리고 **이 파일을 덮어썼다.**
4. 2차 보고는 페이지가 삭제된 뒤의 검사라 벡터가 0으로 나온 것이며 무효다. 다만 그 보고가 아니었다면 메인은 **합성 케이스에 벡터가 실제로 들어갔는지 한 번도 확인하지 않은 채** 결론을 냈을 것이다.
5. 메인이 케이스를 재생성하고 **구조를 실측한 뒤** 직접 검사·직접 육안 확인해 위 결과를 확정했다.

교훈 두 가지:
- **시험 환경을 검사가 완전히 끝나기 전에 철거하면 안 된다.**
- **합성 케이스는 만든 직후 구조를 실측해야 한다.** 케이스가 잘못 만들어졌으면 "검출기 작동함"도 "검출기 결함"도 둘 다 근거가 없다.
