# Design Guide

- 근거: `design/brief.md`
- 토큰: `design/tokens.json` (값은 여기 복제하지 않는다 — 항상 tokens.json 을 읽는다)

## 1. 한 문단 요약

퇴근길 지하철에서 잠깐 열어봐도 "이번 주말 확정 모임"과 "겹침 경고"가 한눈에 들어오는 청첩장모임 스케줄러. 상태 4칸 분할 대신 홈 하나에 모아 보여주고, 지인은 앱 설치 없이 링크만 열어 회신한다. 부드러운 둥근 카드와 선명한 강조색으로 밋밋하지도, 웨딩 클리셰(핑크·세리프)도 아닌 인상을 만든다.

## 2. 토큰 원칙

- 색: semantic 만 직접 사용, primitive 는 참조 전용
- 간격: `spacing.scale` 값만 허용
- 라운딩: `radius.scale` 값만 허용, concentric_rule 준수
- 타이포: `typography.scale` 만 사용, 임의 px 금지
- 상태(진행·에러·비활성 등): `color.semantic.status` / `response` / `alert` 전용 토큰만 사용, feedback 토큰과 혼용 금지

### 2b. 결정 근거 요약

- 왜 이 강조색인가: 한 화면이 한 색만으로 보이면 "밋밋"하다는 반응(R-G-01)이 있었고, 파스텔이 아닌 또렷한 색(고채도)을 골랐다(W-1-1). 청록 계열은 색온도가 아직 정해지지 않은 상태에서 웨딩 클리셰(핑크)를 피하려는 대안이다.
- 왜 이 글꼴인가: 손글씨체(세리프)도, 동글동글한 서체도 싫다는 반응이 있어(R-G-06, R-G-12) 남은 방향인 중성 산세리프를 쓴다. 제목은 크게, 본문과 크기 차이를 크게 둬 "제목 글씨가 큰 게 좋았다"는 반응(W-2-1)을 반영한다.
- 왜 이 간격 체계인가: 화면이 빽빽한 것보다 여유 있는 쪽을 선호했고(R-G-04, R-G-11), 지인 40~100명 리스트를 스크롤해야 하는 상황(§7)이라 컴포넌트 안 여백은 넉넉히, 리스트 행만 살짝 절제했다.
- 왜 이 라운딩·그림자인가: 둥근 카드가 "깔끔하다"는 반응이 있었다(R-G-02). 다만 형태 축은 아직 확정된 근거가 약해(RULE-03, 사용자 선택으로 채움 — 아래 §9 참고), 둥글고 부드러운 쪽으로 그림자도 넓고 옅게 퍼지게 맞췄다.

## 3. 제약사항 (위반 불가)

- 접근성: 본문 텍스트 대비 4.5:1 이상, 테두리 3:1 이상, 큰 글씨(18pt 이상 또는 14pt bold) 3:1 이상 — 하네스 고정
- 이미지·아이콘 깨짐 0 — 하네스 고정
- [CONSTRAINT] 초대받는 쪽 화면(지인용 링크 회신·확정 안내)은 큰 글씨·진한 대비 필요. 반응으로 덮어쓰지 않는다 (brief §5, A-04).
- 브랜드 색·로고·글꼴 지정 없음 — 하네스 결정 위임 (brief §5).

## 5. 화면별 1등 정보

| 화면 | 1등 정보 |
|---|---|
| 커플 연결 온보딩 | 상대 초대 |
| 홈 — 한 눈 조망 | 이번 주말 확정 모임 + 같은 날 겹침 경고 |
| 지인 풀 | 아직 어느 모임에도 안 묶인 사람 수 |
| 모임 편성 | 선택 인원과 그 사람의 중복 소속 |
| 모임 상세(조율) | 회신 현황(n/N)과 마감까지 남은 시간 |
| 지인용 링크 회신 | 내가 가능한 날짜 고르기 |

## 6. 금지 목록

- 세리프(손글씨체) 서체
- 동글동글한(rounded soft) 서체
- 제목을 배경색 박스·밴드로 감싸기 (단, 경보 표면은 예외 — RULE-01 exception)
- 한 화면을 한 가지 색만으로 채우기

## 7. 핵심 과업 (UX 검증)

| # | 과업 | 시작 화면 | 기대 경로 |
|---|---|---|---|
| T-1 | 지인 40명 등록하고 관계별로 묶기 | 빈 지인 풀 | 빠른 추가 → 관계 태그 → 그룹 인원수 |
| T-2 | 날짜 후보 보내고 회신 모아 확정 | 지인 풀 | 인원 선택 → 모임 생성 → 후보·마감 → 회신 현황 → 확정 |
| T-3 | 양쪽 확정 일정 겹침 확인 | 홈 | 주말 조망 → 같은 날 2건 경고 → 상세 이동 |

## 8. 적합성 기준

- 누가 쓰는가: 결혼 3개월 전 예비부부 2인 공동 사용 + 1회성 부 사용자(초대받은 지인). 사용 상황은 이동 중 짧은 확인.
- 기대되는 신뢰감·분위기: 축하 무드보다 "빠뜨린 게 없다"는 안정감 우선. 단 무채색 정돈으로 기울면 안 됨(밋밋함 회피).
- 함정: 웨딩 클리셰(핑크·꽃·필기체 세리프)와 무채색 대시보드 둘 다 회피 대상.
- PRD 대비 변경 사항(brief §10): 지인 회신은 설치 없는 링크 화면으로 1급 화면 추가(P-01). 홈의 상태 4단계는 탭·필터가 아닌 배지로 축소, "지금 손대야 할 모임" 우선 노출(P-02).

## 9. 가정

- `design/brief.md` §6 참조
- SET-B 선택으로 형태 축(RULE-03, 둥근 카드·큰 라운딩)이 채워졌다: 근거는 사용자의 세트 선택이며 이유는 남기지 않았다(`[NO_REASON]`).
- 미적용 기준 (confidence=proposed, §4 미반영): RULE-01(제목 위계·박스 금지, 배수 미정), RULE-03(형태 규칙 미확정), RULE-04(타이포 계열 미확인), RULE-05(홈 상태 표시 방식 미정), RULE-06(초대 화면 구체 수치 미정). 이들은 방향성 참고용이며 A/C 판정 대상이 아니다.
