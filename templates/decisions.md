# Decisions

증거는 기록상 사실 / 사용자 관찰 / 개선 가설 / 미검증으로 구분한다. 에이전트 비평과 사용자 수행을 섞지 않는다.

## 비교할 축

## 레퍼런스 → 정밀 구현 기준안

주 레퍼런스·원본 화면 / 기준 HTML 버전 / 나란히 보는 보드 / 동일 표시 배율:

| 원본의 구체적 특징·위치 | HTML 대응 영역 | 유지/필요한 변형/의도치 않은 이탈/미검증 | 변경 이유·공간/과업 영향 | 실제 대조 캡처·수정 결과 |
|---|---|---|---|---|

제품 과업과 양립하는 시각 관계를 특징별로 대조한다. 제품에 필요한 변형은 delivery.md의 과업 ID·행동·상태 근거로 연결한다. 외형 유사도만으로 품질 통과를 판정하지 않는다.
추가 대안 필요 여부 / 해결할 미정 결정 / 기준안에서 바꾸는 부분:

| 후보·이미지/보드 | 바꾼 요소·고정한 요소 | 시각 조화/인상 비평 | 과업/가독성 비평 | 사용자 반응 원문 |
|---|---|---|---|---|

추천 / 선택 또는 명시적 위임 / 단점·남은 트레이드오프:

사용자 이유는 선택 사항이며 없으면 추정해 채우지 않는다. 차이 모름 / 둘 다 거절 / 명시적 위임은 구분하고 에이전트의 적용 해석·후속 처리를 기록한다. 전문 비평 칸은 에이전트가 작성한다.
